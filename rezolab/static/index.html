Aide — RézoLab

Outil de capture et d'analyse réseau pédagogique : on voit les paquets passer, se dérouler et se cartographier. À n'utiliser que sur des réseaux qui vous appartiennent ou avec autorisation.

1. Démarrer

  • Lancez sudo bash scripts/run.sh (Linux), scripts/RezoLab.command (macOS) ou scripts\run_windows.bat (Windows) : les droits root/administrateur sont requis pour capturer. Puis ouvrez http://127.0.0.1:8420.
  • Choisissez l'interface dans le bandeau (ex. wlp2s0). Avec un VPN, tun0 montre le trafic en clair, l'interface physique seulement le tunnel chiffré. L'adresse IP et la passerelle affichées suivent l'interface choisie.
  • Cliquez ▶ Capturer, puis ■ Stop. 📂 Pcap importe un fichier de capture, 🗑 Vider efface tout.

2. Le bandeau du haut

  • Filtrer par IP : ne garde que les paquets de/vers une machine.
  • Rejouer / Lire / Vitesse : relit la capture pas à pas avec animation ; la barre de progression se déplace à la souris.
  • Protocoles · Paquets · Détail : masquent ou affichent les volets (la vue centrale s'agrandit). Votre choix est mémorisé.
  • ☾ / ☀ : thème sombre ou clair. L'adresse IP et la passerelle sont rappelées en haut à droite.

3. Menu « Protocoles » (à gauche)

  • Cochez DNS, ICMP, DHCP, HTTP/S, Telnet, FTP, SSH, TCP, UDP, ARP pour limiter la capture et l'affichage. Aucun choix = tout (IPv4 et ARP).
  • IPv6 : désactivé par défaut ; à choisir avant de capturer. rDNS : affiche le nom des serveurs distants grâce à des requêtes DNS inverses (elles sont masquées de la capture).
  • Conseil pédagogique : choisissez les protocoles avant de lancer la capture ou de rejouer un pcap, pour repérer plus facilement les paquets qui vous intéressent (ex. DNS puis TCP pour suivre une navigation ; Telnet ou FTP pour voir un échange en clair). Cochés avant « Capturer », ils limitent la capture elle-même (filtre BPF) ; cochés après, ils masquent seulement l'affichage.

4. Les vues

  • Chemin animé : le trajet de chaque paquet entre le client, le routeur, Internet, le serveur et le résolveur DNS (affiché dès la première requête DNS). Bleu = aller, vert = retour ; l'étiquette indique le type (TCP SYN, DNS query…).
  • Diagramme de séquence : un échange par ligne, avec à droite l'adresse ou le domaine distant. L'en-tête reste visible quand on fait défiler.
  • Flux TCP : sélectionnez un paquet TCP, puis « Suivre le flux ». Modes Décodé (HTTP, Telnet), ASCII, Hex, Paquets. Les identifiants en clair (HTTP Basic, cookies, formulaires, Telnet, FTP, POP3, IMAP, SMTP) sont listés et surlignés. TLS et SSH restent chiffrés.
  • Cartographie : les machines du réseau autour du routeur. Passif : elles apparaissent avec le trafic vu et la table des voisins du système (par exemple après un nmap -sn). Actif : ▶ Scanner fait un balayage ARP puis un scan SYN de ports (plage et ports modifiables). Les machines « non confirmées » sont grisées (cache ARP, peut-être éteintes).
  • Astuce : lancez un nmap -sn 192.168.1.0/24 (adaptez la plage) dans un terminal pendant que RézoLab tourne : ce balayage sans scan de ports complète la cartographie. Les machines découvertes apparaissent grâce à la table des voisins du système et aux réponses ARP capturées (ne filtrez pas l'ARP). Avec les droits root, nmap utilise l'ARP, plus fiable en réseau local. Ne scannez que vos propres réseaux.

5. Travailler avec la carte

  • Molette : zoom ; glisser : déplacer ; double-clic : recentrer.
  • Clic sur une machine : fiche à droite (nom, MAC, fabricant, ports et services, état). Le type d'appareil est deviné ; changez-le dans la liste « Type » pour modifier l'icône.

6. Panneau « Vue d'ensemble » et tableau

  • Cliquez un paquet du tableau « Flux de paquets » pour voir son détail. Les pastilles de couleur indiquent le protocole.

7. Bon à savoir

  • Si rien n'apparaît : vérifiez l'interface, les droits root et les filtres cochés.
  • Import de pcap/pcapng impossible avec le navigateur (Firefox Snap/Flatpak, fichier créé avec sudo…) : utilisez le bouton 📁 Chemin et saisissez le chemin complet du fichier ; RézoLab le lit lui-même. On peut aussi le passer au lancement : sudo bash scripts/run.sh /chemin/capture.pcap.
  • Si le navigateur lit mal le fichier : il doit être lisible par votre navigateur. Un fichier créé avec sudo peut demander sudo chown $USER fichier.pcap ; avec un navigateur Snap/Flatpak, copiez-le dans votre dossier personnel.
  • Limites : seul le TCP est conservé pour « Suivre le flux » ; l'UDP et le contenu chiffré ne sont pas lisibles ; les types d'appareils sont des estimations.
  • Fermer cette aide : Échap, la croix, ou un clic en dehors.
